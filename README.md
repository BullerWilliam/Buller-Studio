# Buller Studio

Buller Studio is a native C#/.NET 8 Windows game editor and runtime. It renders a local 3D workspace, manages scene objects and assets, runs Lua X scripts, and builds standalone Windows games.

## Run the editor

Install the .NET 8 SDK, then from this folder run:

```powershell
dotnet restore BullerStudio.csproj
dotnet run --project BullerStudio.csproj
```

The app opens to a dedicated Home screen; no editor is shown until you create or open a project. Home includes templates, recent local projects, search, and three-dot build/delete actions. Projects are stored under `Documents/Buller Studio Projects/<project>/` with `game.buller.json` and an `assets/` folder.

## Editing

- Create objects from the `+` button on a compatible Explorer object or **Model → Insert**; search the insert menu to filter object types. The Workspace always keeps one Camera.
- Explorer includes the Roblox-style `StarterGui` service. Existing projects and scripts using `Gui` continue to resolve to the same service; in Lua X, `game:GetService("StarterGui")` and `game.StarterGui` are supported.
- Explorer includes `SoundService`; Lua X supports `game.SoundService` and `game:GetService("SoundService")`. Its `Volume` property sets the master playback level. Place global Sounds and SoundGroups under it.
- Add an `EchoSoundEffect` under a Sound or SoundGroup. Set `Enabled`, `Delay` (0.01–5 seconds), `Feedback` (0–1), `DryLevel`, and `WetLevel` in Properties or Lua X; its delay line processes audio during play and follows live property changes.
- Add a `FlangeSoundEffect` under a Sound or SoundGroup. Edit `Depth` (0.01–1), `Mix` (0–1), and `Rate` (0–20 Hz) in Properties or Lua X; the play audio path applies the sweeping delay in real time.
- Add a `TremoloSoundEffect` under a Sound or SoundGroup. Edit `Depth` and `Duty` (0–1) and `Frequency` (0.1–20 Hz) in Properties or Lua X; playback varies volume with a repeating tremolo.
- Add a `ReverbSoundEffect` under a Sound or SoundGroup. Adjust `DecayTime` (0.1–20 seconds), `Density`, and `Diffusion` (0–1), plus `DryLevel` and `WetLevel` (-80 to 10 dB) in Properties or Lua X; playback adds a multi-delay reverb tail.
- Insert Block, Ball, and Cylinder Parts, WedgePart, CornerWedgePart, TrussPart, SpawnLocation, Seat, MeshPart, Models, Folders, Humanoid, and PointLight, SpotLight, SurfaceLight, Decal, Texture, Sound, SoundGroup, PitchShiftSoundEffect, EchoSoundEffect, FlangeSoundEffect, TremoloSoundEffect, ReverbSoundEffect, ProximityPrompt, ClickDetector, Highlight, WeldConstraint, BodyForce, BodyThrust, RocketPropulsion, VectorForce, LineForce, Torque, SpringConstraint, TorsionSpringConstraint, RopeConstraint, RodConstraint, BallSocketConstraint, HingeConstraint, PrismaticConstraint, CylindricalConstraint, PlaneConstraint, UniversalConstraint, RigidConstraint, LinearVelocity, AlignPosition, AlignOrientation, or AngularVelocity objects. A Humanoid belongs under a Model, with one Humanoid per Model. Lights, Decals, Textures, prompts, and click detectors are children of a 3D part; Sound can also sit under Workspace, SoundService, a Folder, or a Model. SoundGroups can be placed under SoundService and shared by Sounds. Add PitchShiftSoundEffect under a Sound or SoundGroup, then set its Enabled checkbox and Octave multiplier (0.5–2, where 1 leaves pitch unchanged); pitch shifts while playback speed is preserved. A Highlight can be a child of a part or Model. A Part's Shape and a light's color, brightness, range, and enabled state are editable in Properties; SpotLight also has rotation, and SurfaceLight points outward from its selected Face. An enabled SpawnLocation places the play-mode character on its pad.
- Add `ColorCorrectionEffect` under Lighting or Camera. Edit `TintColor`, `Brightness` (-1 to 1), `Contrast`, and `Saturation` (-1 to 1) in Properties or Lua X; the effect is saved with the project and applies to scene materials in the editor and play preview.
- Set a Model's `PrimaryPart` to a BasePart descendant in Properties or Lua X. Model move and rotate tools use that part's position and rotation as the pivot; clearing PrimaryPart returns the pivot to the model bounds center, and removing the part preserves the last pivot position.
- Add an `AlignOrientation` under a part or Attachment and assign `Attachment0`; `TwoAttachment` mode copies the other attachment's orientation, while `OneAttachment` mode uses its `Rotation` target in degrees. Responsiveness, `MaxAngularVelocity` (radians per second), maximum torque, rigidity, and reaction torque can be edited in Properties or Lua X.
- Add an `AngularVelocity` under a part or Attachment and assign `Attachment0`; its target `AngularVelocity` is measured in radians per second. `RelativeTo` supports `World`, `Attachment0`, or `Attachment1`; set `Attachment1` to use that frame, and enable `ReactionTorqueEnabled` to apply opposing torque there. `MaxTorque`, target velocity, and reaction torque can be edited in Properties or Lua X. Parts also expose runtime `AssemblyAngularVelocity` in radians per second.
- Add a `Torque` under a part or Attachment, assign `Attachment0`, and set a three-component `Torque` vector to apply constant angular acceleration during play. `RelativeTo` supports `World`, `Attachment0`, or `Attachment1`; its default is `Attachment0`. Properties and Lua X both support the torque vector and frame.
- Add a `SpringConstraint` under a part, Model, or Attachment and assign `Attachment0` and `Attachment1`. `FreeLength`, `Stiffness`, `Damping`, and `MaxForce` control its spring and damper force; `LimitsEnabled` exposes `MinLength` and `MaxLength`. `CurrentLength` reports the live distance. These settings save with the project and work in Properties and Lua X; the play solver approximates spring forces between the two attached parts.
- Add a `BodyForce` under a BasePart to apply a constant force along the world axes. Edit its `Force` vector in Properties or Lua X; it saves and clones with the project. It is available for legacy project compatibility; `VectorForce` is the attachment-based alternative.
- Add a `BodyThrust` under a BasePart to apply an assembly-relative force at an assembly-relative `Location`. An offset force also rotates the assembly; both vectors can be edited in Properties or Lua X. Its default force is upward.
- Add `RocketPropulsion` under a BasePart, assign a BasePart `Target` or set a world `TargetOffset`, then call `Fire()` to follow and face it. `Abort()` stops tracking, and `ReachedTarget` fires once when the assembly enters `TargetRadius`; thrust, speed, turning, and torque limits are editable in Properties or Lua X.
- Add a `TorsionSpringConstraint` under a part, Model, or Attachment and assign `Attachment0` and `Attachment1`. `Stiffness`, `Damping`, and `MaxTorque` control its angular spring; `LimitsEnabled` exposes `MaxAngle` and `Restitution`. `CurrentAngle` reports the live angle between the secondary axes of the attachments. `Coils` and `Radius` are editable spring appearance settings. These settings save with the project and work in Properties and Lua X; the play solver applies spring and damping torque to the attached parts.
- Add a `RopeConstraint` under a part, Model, or Attachment and assign both attachments. `Length` limits how far they can separate, while `Restitution` controls bounce at the limit. Enable `WinchEnabled` to drive the attachments toward `WinchTarget` using `WinchSpeed`, `WinchResponsiveness`, and `WinchForce`. `CurrentLength` reports the live distance. These settings save with the project and are available in Properties and Lua X; the play solver approximates rope tension and winch forces.
- Add a `BallSocketConstraint` under a part, Model, or Attachment and assign both attachments. The play solver keeps their attachment points together, limits tilt and twist when enabled, applies `Restitution` at those limits, and damps relative rotation with `MaxFrictionTorque`. `Radius`, `UpperAngle`, `TwistLowerAngle`, and `TwistUpperAngle` are editable in Properties and Lua X and persist with the project.
- Add a `HingeConstraint` under a part, Model, or Attachment and assign both attachments. The play solver joins the attachment positions, aligns their X axes, applies angular limits and restitution, and supports `Motor` and `Servo` actuators. `ActuatorType`, motor speed/torque/acceleration, servo target/speed/torque, and limit angles are available in Properties and Lua X; `CurrentAngle` is read-only.
- Add a `PrismaticConstraint` under a part, Model, or Attachment and assign both attachments. The solver keeps the joint points aligned, locks relative rotation, and allows translation along the attachments' X axes. Limits and restitution are supported, as are `Motor` velocity actuation and `Servo` position actuation. `CurrentPosition` reports signed separation along the joint axis; all actuator and limit settings are available in Properties and Lua X.
- Add a `CylindricalConstraint` under a part, Model, or Attachment and assign both attachments. It combines X-axis sliding with rotation around an `InclinationAngle`-adjusted axis. Linear and angular motors, servos, limits, and current position/angle are available in Properties and Lua X.
- Add a `PlaneConstraint` under Workspace, a part, Model, or Attachment and assign `Attachment0` and `Attachment1`. It keeps Attachment1 on the plane through Attachment0, whose primary X axis is the plane normal. Both parts remain free to translate and rotate along the plane. It is available in Properties and Lua X and persists with the project.
- Add a `UniversalConstraint` under a part, Model, or Attachment and assign both attachments. It keeps their secondary axes perpendicular, with optional primary-axis cone limits controlled by `LimitsEnabled`, `MaxAngle`, and `Restitution`. `Radius` sets the display radius. The settings are available in Properties and Lua X and persist with the project.
- Add a `RigidConstraint` under a part, Model, or Attachment and assign `Attachment0` and `Attachment1`. It applies spring-damper forces to bring the attachment points together and angular correction to align their frames. The setting and attachment references are available in Properties and Lua X and persist with the project.
- Add a `RodConstraint` under a part, Model, or Attachment and assign both attachments. The solver keeps them at the configured `Length`, reports their actual `CurrentDistance`, and supports per-attachment tilt limits. `Length`, `Thickness`, `LimitsEnabled`, `LimitAngle0`, and `LimitAngle1` are available in Properties and Lua X.
- The viewport's options menu controls grid snapping for Move, Scale, and Rotate and lets you choose move and rotation increments. These settings save with each project and are included in undo and redo.
- Insert BoolValue, IntValue, NumberValue, and StringValue under compatible Workspace, GUI, or ReplicatedStorage objects to store simple typed data. Value objects can contain child objects. Edit `Value` in Properties; values persist with the project. In Lua X, read or assign `.Value`, call `:SetProperty("Value", value)`, and connect `Changed` to receive the new value. `Instance.new` also creates these objects during play. IntValue accepts whole numbers within Lua's exact integer range (±9,007,199,254,740,991).
- Insert Vector2Value, Vector3Value, and Color3Value in the same hierarchies. Their `Value` fields store a two-component vector, three-component vector, or a `#RRGGBB` color; Lua X reads and writes them as `Vector2`, `Vector3`, and `Color3` values. `Changed` receives the new typed value. They also support `Instance.new`, cloning, and project save/load.
- Insert ObjectValue to store a reference to another project object. Choose its `Value` with the Properties object picker or assign an Instance or `nil` in Lua X. Its `Changed` event receives the new reference. Cloning a Model redirects references to objects inside the clone and keeps references to objects outside it; deleting a referenced object clears the value.
- Any object can store custom Attributes in the Properties panel. Add a String, Boolean, Number, Vector3, or Color3 attribute, edit or delete it, then save it with the project. Lua X exposes `instance:SetAttribute(name, value)`, `GetAttribute(name)`, `GetAttributes()`, `AttributeChanged`, and `GetAttributeChangedSignal(name)`. Assign `nil` to delete an attribute. Signals fire only when a value changes and run after the current script step.
- Any object can have string Tags in the Properties panel. Tags save with the project and copy when the object is cloned. In Lua X, use `instance:AddTag(tag)`, `RemoveTag(tag)`, `HasTag(tag)`, and `GetTags()`, or `game:GetService("CollectionService")` for `AddTag(instance, tag)`, `RemoveTag(instance, tag)`, `HasTag(instance, tag)`, `GetTags(instance)`, `GetTagged(tag)`, and `GetAllTags()`. `GetTagged` searches objects currently in the game tree. `GetInstanceAddedSignal(tag)` and `GetInstanceRemovedSignal(tag)` fire when a tag is changed or a tagged object enters or leaves that tree.
- Insert a Configuration to group editable value objects and other children under a model, part, service, or GUI hierarchy. It behaves as a container in Explorer, survives save/load and cloning, and can be created with `Instance.new("Configuration", parent)` in Lua X.
- Insert a UIGradient under a Frame, TextLabel, TextButton, ImageLabel, or ImageButton to render a two-color gradient on that object's background, text, and image where applicable. The gradient combines with the object's base colors. Edit StartColor, EndColor, Rotation, and Enabled in Properties, or create and change it from Lua X with `Instance.new("UIGradient", frame)` and Color3 values for its two colors. The gradient appears in the editor preview and play mode, and survives save/load and cloning.
- UICorner accepts a UDim CornerRadius in Properties and Lua X. Its scale uses the shorter rendered side, and the four individual corner radius properties can use different UDim values. Setting CornerRadius updates all four corners; older saved pixel radii remain valid.
- Insert UIShadow under a GUI object for shape or text shadows. Properties and Lua X expose UDim BlurRadius, UDim2 Offset and Spread, Color, Transparency, Enabled, Inset, ShowBehindParent, Mode, and ZIndex. Multiple shadows render in ZIndex order, follow the parent rotation and UICorner, and save with the project. A UIGradient child can tint the shadow. The preview uses WPF blur, so edge masking and inset softness are approximations of Roblox rendering.
- GUI objects expose BackgroundTransparency, text controls expose TextTransparency, and image controls expose ImageTransparency in Properties and Lua X. Each value runs from 0 (opaque) to 1 (invisible); these settings also apply when the object has a UIGradient.
- TextBox exposes PlaceholderText, MultiLine, TextEditable, and ClearTextOnFocus in Properties and Lua X. Play mode supports placeholder hints, line breaks, read-only entry, and clearing when an editable box receives focus; the editor preview keeps text boxes read-only.
- Insert UIPadding under a GUI object to inset its children. PaddingLeft, PaddingTop, PaddingRight, and PaddingBottom accept scale and pixel offset pairs in Properties or `UDim` values in Lua X, such as `padding.PaddingLeft = UDim.new(0, 12)`. Padding affects free placement, scaled sizes, and list and table layouts in the editor preview and play mode.
- Insert UIScale under a GUI object to scale that object and its descendants visually. Its Scale property is editable in Properties and Lua X, and horizontal or vertical list layouts reserve space for the scaled result. UIScale combines with GUI Rotation and persists in saved projects.
- Insert UIAspectRatioConstraint under a GUI object to keep a chosen width-to-height ratio. AspectRatio, AspectType (FitWithinMaxSize or ScaleWithParentSize), and DominantAxis (Width or Height) are editable in Properties and Lua X. The constraint renders in the editor preview and play mode and survives save/load. Older projects using UIAspectRatio remain supported.
- Insert UISizeConstraint under a GUI object to clamp its rendered width and height between MinSize and MaxSize pixel values. The limit applies to scaled sizes and layout assigned sizes in the editor preview and play mode; edit it in Properties or from Lua X with Vector2 values. The object saves and clones with the project.
- TextLabel, TextButton, and TextBox have a TextScaled checkbox that fits their text to the rendered control size. Insert UITextSizeConstraint under one of these controls to set MinTextSize and MaxTextSize; the limits also clamp a fixed TextSize. Properties, Lua X, editor preview, play mode, and project save/load support these settings.
- UIListLayout arranges GUI children with FillDirection, UDim Padding (scale plus pixel offset), HorizontalAlignment, VerticalAlignment, and SortOrder. These settings are available in Properties and Lua X; older LayoutDirection and LayoutSpacing scripts still work. Spacing uses each child's rendered size after aspect and size constraints are applied.
- Insert UIFlexItem under a GUI child controlled by UIListLayout to make that item Grow, Shrink, Fill, or use Custom GrowRatio and ShrinkRatio weights. ItemLineAlignment sets that item's cross-axis alignment, including Stretch. Its properties are available in Properties and Lua X, and save with the project.
- Insert UIGridLayout under a GUI object to arrange children in fixed cells. CellSize and CellPadding use UDim2 scale and offset values; FillDirection selects horizontal or vertical filling, and FillDirectionMaxCells limits cells per row or column (`0` chooses from available space). It works with UIPadding and appears in the editor preview and play mode. UITableLayout remains available for older projects.
- GUI objects have ZIndex and LayoutOrder properties in Properties and Lua X. ZIndex controls which overlapping sibling draws on top; LayoutOrder controls placement in list, grid, and table layouts without changing Explorer order. Equal values keep the Explorer order.
- ScreenGui exposes Enabled and DisplayOrder in Properties and Lua X. DisplayOrder controls stacking between screen layers, while each layer keeps its own child ZIndex order.
- GUI objects expose AnchorPoint as a Vector2 fraction from 0 to 1 on each axis. Position is measured from that point, so centered and edge-aligned controls render consistently in the editor preview and play mode. Set AnchorPoint in Properties or Lua X.
- Insert a BindableEvent to send a one-way signal between Lua X scripts during play. Connect with `event.Event:Connect(function(...) ... end)` and send arguments with `event:Fire(...)`; firing returns before listeners run. The returned connection has `Connected` and `Disconnect()`. Events can be saved, cloned, and created with `Instance.new("BindableEvent", parent)`. Play runs in one local process, so these events do not provide network communication; table arguments are currently passed by reference.
- Insert a RemoteEvent or UnreliableRemoteEvent in Workspace, ReplicatedStorage, or a compatible container. Both support `OnServerEvent`, `OnClientEvent`, `FireServer`, `FireClient`, and `FireAllClients`; `OnServerEvent` receives `Players.LocalPlayer` as its first argument and `FireClient` targets that player. Play currently runs in one local process, so these model the Roblox API shape without network isolation. UnreliableRemoteEvent currently uses the same local event delivery as RemoteEvent; unreliable ordering, packet loss, and payload limits are not simulated.
- Insert a RemoteFunction in Workspace, ReplicatedStorage, or a compatible container. Set `OnServerInvoke` or `OnClientInvoke` and call `InvokeServer(...)` or `InvokeClient(Players.LocalPlayer, ...)`; invocations wait for the matching callback and return its values. Play currently runs in one local process, so this models the RemoteFunction API without network isolation or replication.
- Insert a BindableFunction for a request and response between Lua X scripts in the same play process. Assign the write-only `OnInvoke` callback, then call `functionObject:Invoke(...)` to receive its return values. The caller waits if the callback yields or has not yet been assigned; assigning another callback replaces the earlier one. These objects can be saved, cloned, and created with `Instance.new("BindableFunction", parent)`.
- Insert a ModuleScript to share Lua X code. Double-click it in Explorer to edit its source, return a value, then call `require(game.ReplicatedStorage.ModuleScript)` from another script. You can also pass a string path: `./` starts at the calling script's parent, `../` at its grandparent, `@self/` at the script itself, and `@game/` at a service under the game. The module stays dormant until required and runs once per play runtime; later calls receive the same returned value. Callers wait while a module yields or another script is loading it, and recursive requires report an error. ModuleScripts support save/load, duplication, cloning, and `Instance.new`. Asset ID arguments are not supported.
- ReplicatedStorage is a persistent Explorer service for shared folders, models, parts, sounds, values, and Script templates. Retrieve it with `game:GetService("ReplicatedStorage")` or `game.ReplicatedStorage`. Parts kept there are not rendered or simulated. Scripts kept there stay dormant; moving or cloning an enabled one into Workspace or GUI starts it during play. A Script's `Enabled` checkbox controls startup, and changing `Enabled` in Lua X can stop or restart it. Moving a running Script into ReplicatedStorage stops it until it returns to an active hierarchy.
- ServerScriptService and ServerStorage appear as persistent Explorer services. Enabled Scripts under ServerScriptService run during play, including Scripts inside its Folders and Models. Scripts and parts in ServerStorage stay dormant and out of the scene until moved or cloned into an active hierarchy. Use `game:GetService("ServerScriptService")`, `game:GetService("ServerStorage")`, or their `game` properties in Lua X. Play currently runs in one local process; these services organize execution and storage without network replication or separate client/server security contexts.
- Add a LocalScript under StarterGui, inside a ScreenGui, in a StarterPack Tool, or in StarterPlayerScripts / StarterCharacterScripts. Play copies StarterPlayerScripts into the runtime player's `PlayerScripts` object and copies StarterCharacterScripts into each assigned character, then runs those LocalScripts. StarterGui and StarterPack templates are copied into `PlayerGui` and the player's `Backpack` object. `LocalPlayer.Backpack` and `LocalPlayer.PlayerScripts` expose their Roblox-style class names and can be queried with `IsA`. LocalScripts under the player's Character also run; templates in storage services stay dormant. Local and server scripts share one Lua runtime because multiplayer isolation is not implemented.
- StarterPack is a persistent service for player inventory templates. Add a Tool there and it is copied into `Players.LocalPlayer.Backpack` when play starts. Connect `tool.Equipped`, `tool.Unequipped`, and `tool.Activated` in Lua X; while playing, press 1–9 to equip a Tool, click the viewport to activate it, press the same number to unequip, and press Backspace to drop it when `CanBeDropped` is enabled. The Tool properties include `ToolTip`, `RequiresHandle`, `CanBeDropped`, `ManualActivationOnly`, `GripPosition`, and `GripRotation`; Lua X can read and write them. Grip offsets are local to the character's facing direction, and each part keeps its rotation relative to the Handle. `ManualActivationOnly` disables viewport-click activation so scripts can control activation.
- Use `Seat:Sit(humanoid)` or `VehicleSeat:Sit(humanoid)` in Lua X to seat the managed player character directly. VehicleSeats also expose `ThrottleFloat` (W/S) and `SteerFloat` (A/D). Configure `Disabled`, `HeadsUpDisplay`, `MaxSpeed`, `Torque`, and `TurnSpeed` in Properties or Lua X. `AreHingesDetected` reports the number of connected motor or servo hinges. Throttle drives Motor Hinge/CylindricalConstraints on the seat's weld/rigid assembly; steering drives connected Servo hinges. Original hinge targets and speeds are restored when the player leaves.
- Teams is a persistent service for Team objects. Set each Team's TeamColor (`#RRGGBB`) and AutoAssignable flag in Properties; play assigns LocalPlayer to the first auto-assignable Team. Lua X can use `game:GetService("Teams")`, `player.Team`, `player.TeamColor`, and `Instance.new("Team", game.Teams)`; assign `team.TeamColor = Color3.fromRGB(30, 100, 220)` to change a Team's color.
- SpawnLocation supports Neutral, TeamColor, AllowTeamChangeOnTouch, and Duration in Properties and Lua X. A non-neutral pad only spawns players on a matching TeamColor; touching it can assign that Team, and Duration enables a temporary ForceField that blocks Humanoid:TakeDamage.
- Lighting is a persistent Explorer service with Ambient, Brightness, ClockTime, and GlobalShadows properties. It contains a Sky object whose SkyboxFt/Bk/Lf/Rt/Up/Dn image paths can be set in Properties or from Asset Manager. Add one Atmosphere object to control Color, Decay, Density, Haze, Glare, Offset, and Enabled. Add a BlurEffect to Lighting or Workspace.Camera; its Enabled and Size properties apply a Gaussian blur to the 3D viewport, with the largest enabled blur taking effect. Density, Haze, and Glare tint the viewport sky background; distance fog and Roblox's full lighting pipeline are not yet implemented. Lua X can use `game:GetService("Lighting")`, edit Lighting and Atmosphere properties during play, and create them with `Instance.new("Sky", game.Lighting)`, `Instance.new("Atmosphere", game.Lighting)`, or `Instance.new("BlurEffect", game.Lighting)`. Existing Workspace skybox paths still render as fallback faces when a Sky face is empty. The sun direction follows ClockTime approximately.
- Use `instance:Clone()` in Lua X to make an unparented copy of a stored template, then parent the copy into Workspace or GUI. The copy gets new IDs, keeps child properties, and reconnects internal weld references. Set `Archivable` in Properties or Lua X to exclude an object and its descendants from cloning; non-archivable children are omitted. The editor's **Duplicate** command still copies those children and sets the duplicate's own Archivable value to true.
- Import an image in Asset Manager, then use **Use on selected object** with a selected Decal or set its Asset path in Properties. Choose Front, Back, Left, Right, Top, or Bottom in Face. Decals are planar overlays and fit flat part faces best; their texture follows the parent part during editing and play.
- Add a Texture to a part and assign an imported image through Asset Manager or its Asset property. Choose its Face, StudsPerTileU/V, and OffsetStudsU/V in Properties to repeat and shift the image across that face. The tiling updates when the part is resized.
- Add a `SurfaceAppearance` under a `MeshPart` to tint it and apply imported ColorMap, NormalMap, RoughnessMap, MetalnessMap, and EmissiveMaskContent assets. Set maps and emissive tint/strength in Properties or Lua X (`surface.ColorMap = "textures/albedo.png"`); maps affect mesh rendering in the editor and play mode. Roughness and metalness maps are packed into the renderer's shared map format.
- Add a Sound to Workspace or a part and assign an imported WAV, MP3, or WMA asset. Set Playing, Looped, PlaybackSpeed, and Volume in Properties, or call `sound:Play()` and `sound:Stop()` in Lua X. PlaybackSpeed ranges from 0 to 20 and applies during playback. Sounds attached directly to a part fade between RollOffMinDistance and RollOffMaxDistance relative to the play character, or the camera when automatic character creation is off. Audio runs during play tests and in packaged games.
- Add a SoundGroup under SoundService, set its Volume, then assign it to one or more Sounds through the SoundGroup property or `sound.SoundGroup = group` in Lua X. Sounds under SoundService play globally; each Sound's Volume is multiplied by its group Volume and SoundService's master Volume. References save and clone with the project.
- Use **Model → Duplicate** or `Ctrl+D` to clone the selected object and its children, including attached scripts. The clone receives new IDs so it can be edited independently. Ctrl-click objects in Explorer or the viewport to select several at once; selected objects receive outlines, Move, Rotate, and Scale transform the selection together, and the Properties panel edits the primary selection. Duplicate and Delete operate on the selected objects, while Group wraps selected siblings in one Model. Right-click an Explorer object to insert, duplicate, rename, or delete it; `F2` also renames the primary selection.
- Use **Model → Group** or `Ctrl+G` to wrap selected sibling objects in a Model; **Ungroup** or `Ctrl+Shift+G` moves its children back to the parent.
- Edit Position, Rotation (degrees), Size, Color, Material, Transparency, Anchored, CanCollide, CanTouch, CanQuery, Velocity, and CastShadow in Properties. The material picker includes Plastic, SmoothPlastic, Neon, Wood, WoodPlanks, Marble, Basalt, Slate, CrackedLava, Concrete, Limestone, Granite, Pavement, Brick, Pebble, Cobblestone, Rock, Sandstone, CorrodedMetal, DiamondPlate, Foil, Metal, Grass, LeafyGrass, Sand, Fabric, Snow, Mud, Ground, Asphalt, Salt, Ice, Glacier, Glass, ForceField, Cardboard, Carpet, CeramicTiles, ClayRoofTiles, RoofShingles, Leather, Plaster, and Rubber. `Enum.Material` also exposes `Air`; Terrain fill methods use it to clear voxels. Lua X exposes `LookAtRotation(fromPosition, toPosition)`, which returns a Vector3 rotation in degrees; for example, `part.Rotation = LookAtRotation(part.Position, target.Position)` turns a 3D part toward another position. It also works with a Camera in Custom mode. When the positions coincide, it returns zero rotation. Select a Model in Explorer to move or rotate its 3D children together, or use the viewport Scale tool to resize the model uniformly around its pivot. Scaling updates descendant part sizes, positions, and Attachment offsets. Lua X exposes Position and Rotation; those transforms use the shared pivot, which persists in saved projects.
- Lua X `Vector2` values support componentwise arithmetic, `Magnitude`, `Unit`, `Perpendicular`, `Dot`, `Cross`, `Angle`, `Lerp`, `FuzzyEq`, `Abs`, `Ceil`, `Floor`, `Sign`, `Min`, `Max`, and `ClampMagnitude`, including the `Vector2.zero` and `Vector2.one` constants.
- Lua X `Vector3` values support componentwise arithmetic, `Magnitude`, `Unit`, `Dot`, `Cross`, `Angle`, `Lerp`, `FuzzyEq`, `Abs`, `Ceil`, `Floor`, `Sign`, `Min`, `Max`, and `ClampMagnitude`, including the `Vector3.zero` and `Vector3.one` constants.
- Workspace has an `AutoManageCharacter` checkbox, enabled by default. When enabled at the start of play, the engine creates a simple character at the first enabled neutral SpawnLocation or one matching LocalPlayer's TeamColor; it uses the largest solid part under the origin when no eligible spawn pad exists. A non-neutral SpawnLocation with `AllowTeamChangeOnTouch` enabled changes LocalPlayer's Team when touched. Use WASD to move, Space to jump, right mouse drag to orbit the follow camera, and the wheel to zoom. The engine respawns this character after it falls out of the world. When the checkbox is off, play starts without a generated character or automatic movement and respawn; the camera retains its configured mode. The `Players` service remains available either way, with a play-only `LocalPlayer` whose `Character` is nil until assigned a Model by a script. `workspace.CurrentCamera` references the play camera. Unanchored BaseParts fall under Workspace Gravity and collide with solid parts. Turn off CanCollide for pass-through parts. Play uses a separate scene copy, so simulated movement and script changes do not alter the editor project. Block collision and touch detection follow Position and Rotation. Equal-sized Ball Parts use spherical contact and raycast geometry. Equal X/Z Cylinder Parts use cylindrical raycasts, top-surface geometry, and sphere/cylinder or parallel cylinder/cylinder contacts; cylinder/box contacts and sweeps and wedges still use box approximations. Nonuniform Ball parts use ellipsoid raycasts and support heights, with box-approximate contacts and sweeps.
- Workspace includes the `Terrain` object. Lua X supports `workspace.Terrain:FillBlock(position, size, material)`, `FillBall(position, radius, material)`, `FillCylinder(position, size, rotation, material)`, `FillWedge(position, size, rotation, material)`, `ClearBlock(position, size)`, and `Clear()`. The shape methods use Position and Rotation vectors in degrees and fill or clear a collidable 4-stud voxel grid; `Enum.Material.Air` clears cells intersecting the selected shape. Generated cells stay out of Explorer. Terrain materials include WoodPlanks, Basalt, Slate, CrackedLava, Concrete, Limestone, Pavement, Brick, Cobblestone, Rock, Sandstone, Grass, LeafyGrass, Sand, Snow, Mud, Ground, Asphalt, Salt, Ice, and Glacier.
- The play-only avatar appears under Workspace as `PlayerCharacter` with a `HumanoidRootPart`, a Humanoid, and visible body parts when automatic character management is enabled. Scripts can find it through `game:GetService("Players").LocalPlayer.Character`; it is not saved into the project. Each player also gets a runtime `PlayerGui` containing Archivable ScreenGui copies from `StarterGui`, so scripts can edit `Players.LocalPlayer.PlayerGui` without changing the saved templates. Its visual parts have `CanTouch` disabled so they do not generate contacts with its collision root. The Humanoid's `WalkSpeed` and `JumpPower` control movement; zero `Health` fires `Died` and respawns the generated character with `MaxHealth`.
- A Seat accepts the automatically managed character when it lands on its rotated collision surface. Movement pauses while seated; press Space to stand and jump. `Seat.Occupant` returns the Humanoid in Lua X, or nil when vacant. Seats can be placed and edited like other BaseParts.
- Insert a `BodyVelocity` under a BasePart to drive it toward a target Velocity. Set its per-axis `MaxForce` and proportional gain `P` in Properties or Lua; force is applied during play and respects the part's `Anchored` and collision state.
- Insert a `BodyPosition` under a BasePart to drive it toward a target Position. Set its per-axis `MaxForce`, proportional gain `P`, and damping `D` in Properties or Lua.
- Insert a `BodyGyro` under a BasePart to turn it toward a target Rotation. Set per-axis `MaxTorque`, proportional gain `P`, and damping `D` in Properties or Lua; angles use degrees, consistent with BasePart Rotation.
- Insert a `BodyAngularVelocity` under a BasePart to drive it toward a target angular velocity. Set `AngularVelocity`, per-axis `MaxTorque`, and proportional gain `P` in Properties or Lua.
- Add a ProximityPrompt to a part and edit its ActionText, ObjectText, Enabled state, HoldDuration, MaxActivationDistance, and RequiresLineOfSight in Properties or Lua X. During play with an automatically managed character, approach the part and press or hold E to fire its `Triggered` event; a nonzero HoldDuration requires holding E for that many seconds. The callback receives `Players.LocalPlayer`. When RequiresLineOfSight is enabled, other queryable parts block the prompt; the character and target part are ignored. The nearest available prompt appears at the bottom of the game window.
- Add a ClickDetector to a part and edit its Enabled state and MaxActivationDistance in Properties. During play with an automatically managed character, left-click that part while in range to fire its Lua X `MouseClick` event. The callback receives `Players.LocalPlayer`.
- Equipped Tools expose `Activated`, `Deactivated`, `Equipped`, and `Unequipped` signals, plus `Activate()` and `Deactivate()` methods. Mouse activation fires `Activated` on press and `Deactivated` on release; scripted activation requires the Tool to be equipped.
- Add a Highlight under Workspace, a Folder, a part, or a Model to tint and outline its Adornee in the editor and during play. Set Adornee to a BasePart or Model in Properties or Lua X; older Highlights with no Adornee still target their parent part or Model. Edit Enabled, FillColor, OutlineColor, FillTransparency, and OutlineTransparency in Properties or Lua X. A Model Highlight covers its descendant parts; a closer Highlight targeting a child part takes precedence.
- Add a SelectionBox under Workspace, a Folder, a Model, or a BasePart. Set its Adornee to a BasePart or Model in Properties or Lua X; inserting it under a part or Model fills Adornee automatically. Visible, Color3, Transparency, LineThickness, SurfaceColor3, and SurfaceTransparency control the 3D box in the editor and play view. Model targets use a world-aligned bounding box around their parts. SelectionBox saves and clones with its target reference.
- Add a SelectionSphere under the same 3D parents. Adornee can target a BasePart or Model; Color3 and Transparency control its three outline rings, while SurfaceColor3 and SurfaceTransparency control the enclosing sphere. It follows moving targets in the editor and play view and saves and clones with the project.
- Add a BillboardGui under Workspace, a Folder, Model, or BasePart and place GUI objects beneath it. Set Adornee to a BasePart, Size as UDim2, MaxDistance, Enabled, and AlwaysOnTop in Properties or Lua X. During play it follows the part in screen space, hides behind other queryable parts unless AlwaysOnTop is enabled, and updates as the camera moves. `Instance.new("BillboardGui", part)` creates one already attached to that part.
- Add a SurfaceGui under Workspace, a Folder, Model, or BasePart and place GUI objects beneath it. Set Adornee, Face, PixelsPerStud, MaxDistance, Enabled, and AlwaysOnTop in Properties or Lua X. It follows the selected face in the editor and play preview, scales with the face in the camera view, and respects other queryable parts unless AlwaysOnTop is enabled. `Instance.new("SurfaceGui", part)` attaches it to that part's Front face.
- Add a ForceField to a Model or BasePart. A ForceField in a character Model, on its HumanoidRootPart, or in an ancestor Model prevents `Humanoid:TakeDamage(amount)` from changing Health. Direct Health assignments still work. Negative damage heals when unprotected. `Visible` toggles a simple translucent shield in the editor and play view without removing protection. ForceFields support `Instance.new`, cloning, and project save/load.
- Insert an Explosion under Workspace or create one with `Instance.new("Explosion")`, set Position, BlastRadius, BlastPressure, DestroyJointRadiusPercent, and Visible, then parent it to Workspace. It detonates once during play, reports affected BaseParts through `Hit:Connect(function(part, distance) ... end)`, pushes unanchored parts, breaks nearby WeldConstraints, and defeats unprotected Humanoids inside the joint radius. BlastPressure and DestroyJointRadiusPercent can both be zero for a non-damaging hit query. The play view shows a brief pulse; editor and saved projects keep the editable object. Impulses and visual effects are simplified approximations.
- Insert Fire or Smoke under a BasePart or its Attachment. Fire has Color, SecondaryColor, Size, Heat, Enabled, and TimeScale; Smoke has Color, Size, Opacity, RiseVelocity, Enabled, and TimeScale. Both render moving particle approximations in play and a static preview in the editor. Lua X can create and edit them with `Instance.new("Fire", part)` and `Instance.new("Smoke", part)`; their properties persist with the project.
- Insert Sparkles under a BasePart or Attachment for animated glints. Set SparkleColor, Enabled, and TimeScale in Properties or Lua X, or create it with `Instance.new("Sparkles", part)`. Sparkles also supports the Color alias in Lua X; its appearance is a simple approximation.
- Insert a ParticleEmitter under a BasePart or Attachment. Set Texture, Rate, Size, Color, Transparency, Speed, Lifetime, SpreadAngle, EmissionDirection, Enabled, and TimeScale in Properties or Lua X. Select a project image asset for Texture to render camera-facing billboards; without an image the renderer uses colored 3D particles. Size, Color, and Transparency support keypoints across each particle's lifetime. In Properties, enter a sequence such as `0:1, 0.5:3, 1:0` for Size, `0:#FF0000, 1:#0000FF` for Color, or a single constant value. In Lua X, use `NumberSequence.new(value)`, `NumberSequence.new(start, end)`, or an array of `NumberSequenceKeypoint.new(time, value, envelope)` values; ColorSequence supports colors and `ColorSequenceKeypoint.new(time, color)` values. Scripts can call `emitter:Emit(count)` for a burst or `emitter:Clear()` to remove active particles. Settings and keypoints save and clone with the project; emitted particles do not.
- Insert a Trail under a part or Model, then set Attachment0 and Attachment1 to two Attachments using Properties or Lua X. During play, the moving attachments leave a ribbon that fades after Lifetime seconds. MinLength controls when a new segment is recorded; MaxLength limits the recorded path. WidthScale, Color, and Transparency support constant values or keypoint sequences, and Texture accepts a project image asset. FaceCamera turns the ribbon toward the camera; TextureMode (Stretch, Wrap, Static) and TextureLength control how that image maps along it. Scripts can call `trail:Clear()` to remove active segments. Trail settings save and clone; segment history is temporary.
- `game:GetService("Debris")` (also `game.Debris`) schedules temporary instances for cleanup with `Debris:AddItem(instance, lifetime)`. The default lifetime is 10 seconds; zero removes the instance immediately. Cleanup continues if the scheduling Script is disabled or removed. The service keeps at most 1,000 scheduled items and destroys the oldest when full.
- `game:GetService("RunService")` (also `game.RunService`) exposes `PreSimulation` and `Stepped` before physics, `PostSimulation` after physics, and `Heartbeat`, `PreRender`, and `RenderStepped` near the end of each play frame. Connect with `RunService.Heartbeat:Connect(function(deltaTime) ... end)` and disconnect the returned connection when it is no longer needed. `IsRunning()` is true in play, `IsEdit()` is false, and `IsStudio()` distinguishes editor playtests from packaged games. Buller Studio has one local runtime, so these frame signals do not imply separate client and server execution contexts.
- `game:GetService("UserInputService")` (also `game.UserInputService`) exposes `InputBegan`, `InputChanged`, and `InputEnded`, `IsKeyDown(Enum.KeyCode.W)`, `GetKeysPressed()`, and `GetMouseLocation()`. Input callbacks receive an `InputObject` with `KeyCode`, `UserInputType`, `UserInputState`, `Position`, and `Delta`, followed by a `gameProcessed` flag. The play preview forwards keyboard and mouse button and movement input; losing preview focus releases any keys still held.
- `game:GetService("ContextActionService")` binds named callbacks to keyboard keys, mouse buttons, or mouse movement with `BindAction` or `BindActionAtPriority`. Callbacks receive the action name, `Enum.UserInputState`, and the `InputObject`; `UnbindAction` and `UnbindAllActions` remove bindings.
- Add a WeldConstraint under Workspace, a Folder, Model, or part. Set Part0 and Part1 using the Properties object pickers; adding it under a part fills Part0 automatically. Enabled welds join unanchored parts into one translating assembly during play, and an anchored member holds the assembly still. Lua X can read or assign Part0 and Part1 as BasePart instances. Welds preserve relative positions and rotations when a member is moved or rotated during play. An anchored member controls the assembly when present. Angular velocity rotates the welded assembly as a rigid body around its center of mass; collision checks sample intermediate angular poses against oriented boxes, with simplified contact response.
- Add NoCollisionConstraint under Workspace, a Folder, Model, or part to let Part0 and Part1 pass through each other while they still collide with other parts. Add it under a part to fill Part0 automatically, then choose Part1 in Properties or assign a BasePart in Lua X. Enabled controls the exception; the linked parts and setting survive save/load and cloning.
- Add a VectorForce under an Attachment, part, or Model, then set Attachment0 to an Attachment on the part to push. Force is a three-component vector; RelativeTo can be World, Attachment0, or Attachment1, and Enabled toggles the effect. ApplyAtCenterOfMass moves the force application point to the assembly's center of mass and prevents force-induced rotation. In Lua X, create one with `Instance.new("VectorForce", attachment)` and set `Force = Vector3.new(x, y, z)`. The physics solver treats part volume as unit-density mass and approximates rotation using a scalar moment of inertia.
- Add a LineForce under Workspace, a Model, a part, or an Attachment, then assign Attachment0 and Attachment1. Magnitude applies force along the line between the attachments; ReactionForceEnabled adds an equal and opposite force at Attachment1. InverseSquareLaw scales the force by distance squared and MaxForce caps it. ApplyAtCenterOfMass suppresses force-induced rotation. The properties work in Properties and Lua X, save with the project, and use approximate scalar moments of inertia in play physics.
- Add a LinearVelocity under an Attachment, part, or Model and set Attachment0 to an Attachment on the moving part, or create one with `Instance.new("LinearVelocity", attachment)` in Lua X. Vector mode holds VectorVelocity, Line mode holds velocity along LineDirection, and Plane mode holds two velocity components along PrimaryTangentAxis and SecondaryTangentAxis. RelativeTo supports World, Attachment0, or Attachment1 coordinates. ReactionForceEnabled applies an opposing velocity impulse to Attachment1's assembly when using its frame. ForceLimitsEnabled caps how quickly the solver can reach the target; ForceLimitMode selects a magnitude cap (MaxForce) or per-axis caps (MaxAxesForce for Vector mode and MaxPlanarAxesForce for Plane mode). Line mode uses MaxForce. These settings work in Properties and Lua X, save and clone with the project, and drive welded assemblies together. This is a translational approximation using the engine's unit-density mass.
- Add AlignPosition under an Attachment, part, or Model. OneAttachment mode moves Attachment0 toward a world Position; TwoAttachment mode moves it toward Attachment1. Set Responsiveness, MaxVelocity, MaxForce, RigidityEnabled, ReactionForceEnabled, and ApplyAtCenterOfMass in Properties or Lua X. Unless ApplyAtCenterOfMass is enabled, force from an offset Attachment can also rotate its part or welded assembly; this uses an approximate scalar moment of inertia.
- Add an Attachment under each of two parts, then insert a Beam and set Attachment0 and Attachment1 with the Properties object pickers. Attachment Position is relative to its parent part. Small Attachment markers are selectable in the editor viewport and hidden during play. Beams render as tapered colored tubes between the endpoints, follow moving and rotating parts, and expose Enabled, Width0, Width1, Color, and Transparency. Lua X can create both classes with `Instance.new` and set Beam endpoint references to Attachment instances. Cloning a Model that contains the Beam and both Attachments reconnects the clone's endpoints.
- Set `Velocity` or `AssemblyLinearVelocity` in Lua X to move an unanchored BasePart during play. Welded parts share translation and velocity. Collision stops the affected velocity component; bounce and friction are not simulated.
- The Workspace Camera has `Mode` (`Custom` or `Subject`), `Position`, `Rotation`, `Subject`, and `FieldOfView` properties. Custom mode uses Position and Rotation. Subject mode orbits the selected BasePart. The scene view uses this same camera.
- Use right mouse drag to turn the editor camera, WASD/QE to move it, and the wheel to zoom. The editor camera controls remain separate from the play-mode character and follow camera.
- Import PNG/JPEG/BMP/GIF images, WAV/MP3/WMA audio, and Wavefront OBJ meshes into the local assets list. Assign an asset's relative path, such as `assets/tree.obj`, to a MeshPart or `assets/logo.png` to an ImageLabel. Lua X can also access imported asset paths.
- `Ctrl+S` saves, `Ctrl+Z` undoes, `Ctrl+Shift+Z` redoes, `Ctrl+D` duplicates, and `Delete` removes a selected non-camera object.
- The editor uses a Studio-style ribbon and dock layout: the 3D viewport in the center, Explorer and Properties on the right, and Output/Asset Manager below. Manage assets only in Asset Manager. Drag panel headers to snap major docks to another workspace region.
- **Run Script** opens an isolated play window and runs the selected Script there, forwarding its output to the editor. Its scene changes stay in the play copy. **Play** runs all enabled scripts in a separate play window.

## Lua X

Scripts use a sandboxed Lua interpreter. Instances are available by name and under `game.Workspace`. Useful APIs include:

Lua X completion suggests object members, `WaitForChild` names from the current hierarchy, asset paths, service names, camera modes, and property names for `SetProperty`/`GetProperty`.

```lua
local part = game.Workspace:WaitForChild("Part")
part:SetProperty("Position", {X = 0, Y = 3, Z = 0})
part:SetProperty("Shape", "Ball")
part:SetProperty("Material", "Neon")
part.Anchored = false
part.AssemblyLinearVelocity = Vector3.new(5, 0, 0)
print(part:GetProperty("Name"))
part.Touched:Connect(function(other)
    print("Touched", other.Name)
end)
local prompt = part:WaitForChild("ProximityPrompt")
prompt.Triggered:Connect(function(player)
    print("Used by", player.Name)
end)
local detector = part:WaitForChild("ClickDetector")
detector.MouseClick:Connect(function(player)
    print("Clicked by", player.Name)
end)
local humanoid = game.Players.LocalPlayer.Character:WaitForChild("Humanoid")
humanoid.Died:Connect(function() print("Character died") end)
humanoid.WalkSpeed = 12
local score = Instance.new("IntValue", workspace)
score.Name = "Score"
score.Changed:Connect(function(value) print("Score:", value) end)
score.Value = score.Value + 1
local template = game.ReplicatedStorage:FindFirstChild("Tree")
if template then
    local tree = template:Clone()
    tree:SetProperty("Parent", workspace)
end
local imagePath = GetAssetPath("logo.png")
```

`SetProperty(instance, property, value)`, `GetProperty(instance, property)`, `WaitForChild(parent, childName)`, `ConnectTouched(instance, callback)`, `GetAssetPath(assetName)`, and `print(...)` are available. `waitforchild` and lowercase `touched` aliases are supported. Touched events are generated for overlapping BasePart bounds when both parts have `CanTouch` enabled.

`instance:WaitForChild(childName, timeout?)` yields the current script until that direct child appears; it returns `nil` when the optional timeout elapses. This allows scripts to wait for objects that another script creates later.

Instances expose `FindFirstChildOfClass(className)` and `GetDescendants()` alongside `FindFirstChild()` and `GetChildren()`. Models also expose `MoveTo(position)` and `RotateTo(rotation)`; rotation values use degrees and can be read or assigned through the Model's `Rotation` property.

Lua X supports `workspace:Raycast(origin, direction, params?)` for querying 3D parts. The direction vector sets the cast length. A hit returns `Instance`, `Position`, `Normal`, `Distance`, and `Material`; a miss returns `nil`. Queries use rotated part bounds and respect `CanQuery` independently of collision and touch. Use `RaycastParams.new()` with `FilterDescendantsInstances = {modelOrPart}` and `FilterType = Enum.RaycastFilterType.Exclude` (default) or `Include` to filter object trees.

Use `workspace:GetPartsInPart(part, overlapParams?)` to find Workspace parts intersecting a BasePart. `workspace:GetPartBoundsInBox(position, size, rotation?, overlapParams?)` and `GetPartBoundsInRadius(position, radius, overlapParams?)` query part bounds with Position and Rotation vectors. `OverlapParams.new()` supports `FilterDescendantsInstances`, `FilterType` (`Exclude` or `Include`), `MaxParts` (zero means unlimited), and `RespectCanCollide`; otherwise results respect each part's `CanQuery` property.

Use `task.wait(seconds)` to yield until a later play update; it returns the elapsed simulation time. `task.spawn(callback, ...)` starts a separate coroutine immediately, `task.defer(callback, ...)` runs after the current script resume point, and `task.delay(seconds, callback, ...)` runs after the delay. Each scheduling call returns a coroutine that `task.cancel(thread)` can stop while pending or yielded. The global `wait(seconds)` is an alias for `task.wait`. Disabling, moving out of an active hierarchy, or destroying a Script cancels its pending tasks.

Use `TweenService` to animate supported properties over time. `TweenInfo.new` accepts duration, easing style and direction, repeat count, reverse flag, and delay. Tweenable values include numbers, `Vector2`, `Vector3`, `Color3`, and `UDim2`:

```lua
local TweenService = game:GetService("TweenService")
local tween = TweenService:Create(part, TweenInfo.new(1, Enum.EasingStyle.Quad, Enum.EasingDirection.Out), {
    Position = Vector3.new(0, 8, 0),
    Color = Color3.fromRGB(255, 120, 40)
})
tween.Completed:Connect(function(playbackState)
    print(playbackState)
end)
tween:Play()
```

`tween:Pause()` pauses and `tween:Cancel()` cancels a running animation. Replaying a completed or cancelled tween starts it again from the current property values.

During play, `Instance.new(className, parent?)` creates supported scene and GUI objects. Children can be added to a Model before the Model is placed in Workspace. Assign `Parent = nil` to detach an object, or call `Destroy()` to remove it and its descendants. These changes affect the play copy and are not saved to the editor project. For a project with `Workspace.AutoManageCharacter` off, a script can create and assign its own character Model:

```lua
local character = Instance.new("Model")
character.Name = "CustomCharacter"
local root = Instance.new("Part", character)
root.Name = "HumanoidRootPart"
root.Position = Vector3.new(0, 5, 0)
root.Anchored = false
Instance.new("Humanoid", character)
character.Parent = workspace
game.Players.LocalPlayer.Character = character
workspace.Camera.Subject = root
workspace.Camera.Mode = "Subject"
```

Direct `Name` and `Parent` assignments become visible to hierarchy lookups when the current script yields or finishes. Use `instance:SetProperty("Name", name)` or `instance:SetProperty("Parent", parent)` when later lines in the same script need to find the object immediately.

With automatic character management off, scripts control that character's movement and respawn behavior. `Players.LocalPlayer.CharacterAdded` fires with the assigned Model and `CharacterRemoving` fires with the previous Model when it is cleared, replaced, or destroyed; the Players service remains available in either mode.

## Build games

Choose **Included** to embed the project and its assets into the game executable, or **Excluded** to place `game.buller.json` and an `assets/` folder beside the executable. Build output is placed in a named subfolder in Downloads. Builds use `dotnet publish` for a self-contained Windows x64 single-file executable; the .NET SDK and a network connection may be needed on the first build to restore the Windows runtime pack.

## Engine capabilities

The editor includes a Direct3D scene view with primitive shapes, point, spot, and surface lights, directional lighting and shadow mapping, local project persistence, parts and model groups, OBJ mesh and image rendering, planar decals and tiled textures, local sound playback, click and proximity interactions, play-test gravity, solid-part collision, rotating welded assemblies and approximate constraint physics, a spawn and movement controller with Humanoid health and movement settings, camera modes, a Lua X runtime, and included/excluded game packaging. It does not yet include a full rigid-body/contact solver, glTF import, multiplayer, or a full Humanoid state machine and character animation.

- Accessory is available in the object menu and Instance.new; it is a container for a visible Handle part and can be parented to a model for manual avatar assembly.
